# DureClaw vs SSH — 이종 OS 원격 실행 비교 실험

> **한 줄 결론:** SSH는 "이종 인바운드"를 그대로 노출하고, DureClaw는 그걸 "균질 아웃바운드 + 정규화 마커"로 바꾼다. **Windows가 노드에 낄수록 이 차이가 커진다.**

작성: 2026-07-02 · 오케스트레이터 Mac(macOS arm64) → 타깃 Windows 11(NUCBOXG3, x64) · 사설망 Tailscale

---

## 1. 실험 설계

동일한 과제를 두 전송(transport)으로 수행하고 태스크별로 계측한다.

| Arm | 방식 | 측정 상태 |
|-----|------|-----------|
| **A. DureClaw** | 아웃바운드 에이전트 + 마커(`[SHELL]`/`[WRITE:b64]`/`[SCREENSHOT]`) | ✅ **라이브 실측** |
| **B. SSH** | 인바운드 OpenSSH (Mac→Windows) | ⚠️ **셋업 마찰은 실측, 실행 단계는 모델링** (아래 3절 사유) |

**지표:** 라운드트립(round-trip = 오케스트레이터↔노드 왕복 1회), 제어 바이트(instruction+result), 토큰 추정(bytes/4), 벽시계(s), 실패 수.

**시뮬레이션 태스크(난이도·유형 다양화):**

| 태스크 | 내용 | 스트레스 축 |
|--------|------|-------------|
| T1 정보수집 | `hostname`, `ver` | 기본 |
| T2 파일생성·실행 | 파이썬 파일 기록 → 실행 | 인코딩·개행·따옴표 |
| T3 빌드 파이프라인 | 파이썬 작성 → 실행 → PyInstaller onefile exe → exe 실행 | 다단계·경로·셸 |
| T4 산출물 회수 | 빌드된 exe 해시(SHA256) 확인 | 파일 회수 |
| T5 화면 캡처 | 원격 화면 스크린샷 | OS 네이티브 능력 |

---

## 2. Arm A — DureClaw (라이브 실측)

Mac 오케스트레이터 → `builder@NUCBOXG3`(Windows 11), keyless 등록된 노드.

| 태스크 | 라운드트립 | 제어 토큰(추정) | 벽시계 | 실패 | 결과 |
|--------|:---:|:---:|:---:|:---:|------|
| T1 정보수집 | 2 | 20 | 0.1 s | 0 | ✅ hostname·ver |
| T2 파일생성·실행 | 2 | 52 | 0.1 s | 0 | ✅ 실행 출력 |
| T3 빌드 파이프라인 | 4 | 1,123 | 11.5 s | 0 | ✅ **calc.exe 빌드·실행** |
| T4 산출물 회수 | 1 | 63 | 0.4 s | 0 | ✅ SHA256 |
| T5 화면 캡처 | 1 | 65,644\* | 2.2 s | 0 | ✅ PNG 262 KB |
| **합계** | **10** | **≈1,258\*\*** | **14.3 s** | **0** | **5/5 성공** |

\* T5의 토큰은 대부분 스크린샷 이미지(262 KB base64)의 **데이터 페이로드**로, 제어(추론) 토큰이 아니다.
\*\* 합계 제어 토큰은 T5의 이미지 페이로드를 제외한 값(T1~T4 = 1,258). 이미지 포함 시 66,902.

**셋업 비용: 0** — 노드는 keyless 자동 등록(tailnet 자동 승인)으로 이미 붙어 있었고, 인증·방화벽·키 배포가 없다.

## 3. Arm B — SSH (셋업 마찰 실측 + 실행 모델)

### 3-1. 셋업 마찰 — 실측 (실행 단계 도달 실패)

포트 22는 열려 있었으나 **실제 작업 한 줄 전에 인증에서 연속 실패**했다.

| # | 시도 | 결과 |
|---|------|------|
| 0 | `nc :22` 프로브 | ✅ OPEN (sshd RUNNING) |
| 1 | 키 없이 SSH | ❌ Permission denied (publickey,password,...) |
| 2 | 사용자 `~/.ssh/authorized_keys` 프로비저닝 | ❌ 여전히 거부 |
| 3 | ACL 상속 제거(`icacls /inheritance:r`) | ❌ 여전히 거부 |
| 4 | 원인 규명: 대상 계정이 **Administrators 그룹** → `administrators_authorized_keys` 필요 | — |
| 5 | 해당 파일 쓰기 | ❌ **EPERM — UAC 상승 필요**(대화형, 자동화 불가) |

→ **실행 태스크 0/5.** 부가 마찰: cmd 코드페이지 mojibake(`net localgroup` 출력 깨짐), `findstr "..."` 따옴표 파손.

> **부트스트래핑 역설:** SSH를 뚫기 위한 진단·키 프로비저닝을 전부 **DureClaw로** 수행해야 했다(SSH가 스스로 들어가질 못해서). 경쟁 방식이 경쟁 상대를 부트스트랩한 셈.

### 3-2. 실행 단계 — 모델 (인증이 이미 해결됐다고 가정한 낙관적 추정)

인증이 해결됐다면 per-task 비용은 아래로 추정된다. **모델임을 명시**하며, Windows 특유의 실패 축을 함께 표기한다.

| 태스크 | 모델 라운드트립 | 걸리는 이종 축 | 비고 |
|--------|:---:|------|------|
| T1 정보수집 | 2 | — | SSH도 무난 |
| T2 파일생성·실행 | 3~4 | 인코딩·개행·따옴표 | cmd엔 heredoc 없음 → `echo`/리다이렉트 또는 `certutil -decode` 다단계, 또는 별도 scp 채널 |
| T3 빌드 파이프라인 | 6~8 | 셸·경로·인코딩 | 파일쓰기(위) + 경로 백슬래시 + `cd /d` + 빌드 |
| T4 산출물 회수 | 1~2 | — | scp 또는 `certutil` |
| T5 화면 캡처 | 캡처 도구 선배포 필요 | 능력 없음 | **SSH 네이티브 스크린샷 없음** — nircmd/PowerShell Add-Type 배포 후에나 가능(헤드리스 난점) |

## 4. 비교 요약

| 지표 | DureClaw (실측) | SSH (Windows·admin) |
|------|:---:|:---:|
| 온보딩 셋업 | **0** | 대화형 UAC 상승 필요 → **미완** |
| 인증 실패(셋업) | **0** | **4 + 상승 벽** |
| 실제 작업 실행 | ✅ **5/5** | ❌ **0/5** (인증에서 차단) |
| 작업 성공 시 총 라운드트립 | **10** | (모델) 12~18 + 셋업 |
| 대화형 개입(비번/UAC) | 없음 | **필수**(헤드리스 불가) |
| 화면 캡처 | ✅ 마커 1회 | 네이티브 불가 |

## 5. 왜 그런가 — 5축 이종성

Linux↔Mac은 둘 다 POSIX라 SSH가 기대는 전제("키 한 번 → 끝")가 성립한다. Windows가 끼면 5개 축이 동시에 깨진다.

| 축 | SSH(이종 인바운드) | DureClaw(균질 아웃바운드) |
|----|-------------------|--------------------------|
| 셸 | cmd↔PowerShell↔WSL 혼재 | `[SHELL]`이 OS별 셸 자동 선택 |
| 경로 | `C:\` 역슬래시·드라이브·`cd /d` | 경로 그대로, 노드 로컬 해석 |
| 인코딩 | 코드페이지 → mojibake | `[WRITE:b64]` 바이트 그대로 |
| 개행 | CRLF↔LF | base64 → 개행 무관 |
| 인증 | admin_authorized_keys+ACL+UAC | keyless 등록, 인바운드 인증 없음 |

SSH·WinRM·PsExec·WMI 등 **인바운드** 방식은 전부 같은 벽(자격증명·방화벽·상승)에 걸린다. DureClaw는 **아웃바운드 에이전트 + 정규화 마커**로 그 계층 자체를 없앤다.

---

## 6. 정직한 한계

- **SSH가 불리하게 보이는 것은 "Windows·admin·헤드리스" 조합 때문**이다. Linux↔Mac이거나, 키를 최초 1회 대화형으로 심어두면 이후 per-task SSH 비용은 DureClaw와 비슷하다. DureClaw의 이득은 **런타임 속도가 아니라** ① 제로 셋업 온보딩, ② 대화형 자격증명·UAC 불요, ③ 마커 기반 이종-OS 정규화에 집중된다.
- Arm B 실행 단계는 이 환경에서 **측정 불가(모델)** 다 — UAC 상승이 대화형이라 자동화가 완주할 수 없기 때문. 이 "완주 불가"가 곧 이종-OS SSH의 실무 마찰을 보여준다.
- DureClaw도 Windows의 모든 기벽을 지우진 않는다: 생 `[SHELL]`은 cmd.exe에서 돌아 bash 문법을 보내면 깨지고, `[SHELL]` 출력의 코드페이지 mojibake는 남는다(파일쓰기는 `[WRITE:b64]`로 우회됨).
