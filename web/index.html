🔑 키리스 접근 — 시크릿을 미리 나눠주지 않는다

노드는 공유 시크릿을 몰라도 됩니다. 서버에 가입 요청하면 서버가 승인 후 노드별 토큰을 발급합니다. 마스터 시크릿은 어디에도 복사되지 않고, 토큰은 노드마다 개별 폐기할 수 있습니다.

① 가입 · 자동 승인
노드가 POST /api/join → Tailscale 사설망 피어는 즉시 자동 승인(zero-click). 밖에서 오면 운영자 승인 대기.
② 노드별 토큰
서버가 per-node 토큰 발급 → 노드가 캐시. 다음부턴 즉시 재접속. 마스터 시크릿 무노출·개별 폐기 가능.
③ 단일 지시자
워커는 연결·수신·보고만. 업무지시(디스패치)는 마스터 한 곳에서만 — 워커 토큰으로는 지시 불가.
Windows·RPi Zero처럼 인증을 두기 어려운 머신도 그대로 합류. 키 없는 손, 하나의 두뇌.

어디에 위치하는가 — L4→L0 수직 스택

Claude Code 에코시스템에서 대부분의 메타팩토리는 L3에서 구조/설정을 뱉고 외부 런타임에 넘깁니다. DureClaw는 팀을 생성(L3)할 뿐 아니라, 그 팀이 실제로 도는 런타임(L1)·물리 실행(L0)을 소유하고, 산출물을 평가해 되먹이는 자기개선(L4)까지 한 몸으로 가진 유일한 수직 스택입니다. One vertical from self-improvement down to the physical actuator.

L4
RSI / 자기개선 ★ DureClaw 고유
5단계 학습 루프(관측→종합→목적화→지식화→학습·선택) + eval + 결정 동결. 팀 산출물을 평가해 결정론적 스킬로 결정화하고 L3 패턴에 되먹임 — 팩토리 자체를 진화. Recursive self-improvement above the meta-factory.
L3
Meta-Factory / Team-Architecture 이웃: Archon · meta-harness
도메인 문장 → 에이전트 팀 + 스킬. /dureclaw 6패턴(Pipeline · Fan-out/in · Expert Pool · Producer-Reviewer · Supervisor · Hierarchical).
L2
Cross-Harness Workflow 이웃: ECC
스킬·룰·훅 표준화 + 플러그인 마켓플레이스 로더 — 여러 하니스 간 공통 규약.
L1
Orchestration Runtime ★ DureClaw 고유
Phoenix Channel 버스 + MCP + Work Key + DETS 영속 + keyless brain 위임. 팀이 실제로 실행되는 분산 메시지 버스.
L0
Physical Execution ★ DureClaw 고유
edgeclaw(shell·GPIO·신호탑·PA) · webclaw(브라우저) · deskclaw(GUI). Win·mac·Linux·Pi·riscv — 물리 액추에이터까지 "승인=물리 결과".
Archon은 런타임 결정론을 만든다. DureClaw는 L4 결정 동결로 그 결정론을 L0 엣지에 직접 내린다 — 생성·실행·자기개선을 한 수직으로.
🗺 clawfit 에코시스템 맵에서 보면 — DureClaw = L2

clawfit 은 Claude Code 에코시스템의 162+ 도구를 7계층(L1–L7)으로 분류하는 추천 엔진·생태계 맵입니다. 그 기준에서 DureClaw는 L2 — Meta wrappers / harnesses / orchestration: Claude Code·pi 같은 L1 베이스 런타임 위에 올라타는 메타-래퍼/오케스트레이션 슬롯입니다(이웃: SuperClaude · Archon · oh-my-*).

⚠️ 두 렌즈는 직교합니다. clawfit의 L1–L7은 "성숙도 사다리가 아니라 아키텍처 역할"을 가르는 가로 렌즈(어느 슬롯인가). 위의 L4→L0은 세로 렌즈 — DureClaw가 그 L2 역할을 하면서 실제로 자기개선(L4)부터 물리 실행(L0)까지 몇 계층을 직접 소유하는가를 보여줍니다. 같은 사물의 다른 축.

⚡

왜 SSH가 아니라 DureClaw인가

SSH는 "이종 인바운드"를 그대로 노출하고,
DureClaw는 그걸 "균질 아웃바운드 + 정규화 마커"로 바꾼다.
Linux↔Mac은 둘 다 POSIX라 "키 한 번 → 끝". 하지만 Windows가 노드에 끼는 순간 SSH가 기대는 전제가 5개 축에서 동시에 깨진다 — Windows가 낄수록 이 차이가 커진다.
축 SSH — 이종 인바운드 (Windows에서) DureClaw — 균질 아웃바운드
셸cmd ↔ PowerShell ↔ WSL 혼재 — 따옴표·이스케이프 파손[SHELL] 데몬이 OS별 셸 자동 선택
경로C:\… 역슬래시·드라이브레터·cd /d경로를 그대로 전달, 노드가 로컬 해석
인코딩cmd 코드페이지 → mojibake[WRITE:b64] 바이트 그대로 기록
개행CRLF ↔ LF — heredoc·스크립트 깨짐base64 전송 → 개행 무관
인증관리자는 administrators_authorized_keys + 무상속 ACL + UAC 상승keyless 등록 — 인바운드 인증·방화벽·상승 전부 없음
실측 실험: 같은 과제(Mac→Windows 파이썬→exe 빌드)에서 DureClaw는 셋업 0 · 6단계로 exe 완성, SSH는 작업 전 인증에서 4번 실패 + UAC 벽으로 한 줄도 실행 못 함. 차이는 전송 속도가 아니라 온보딩·인증·이종-OS 정규화의 마찰 제거다.
🔄 복원력 · 가시성 — SSH엔 없는 것
서버를 재가동·업그레이드해도 노드가 자동 재접속(지수 백오프)하고, 실시간 대시보드로 fleet 현황을 본다. SSH는 세션이 끊기면 수동 재연결이고, "누가 살아있나"를 보는 화면이 없다.
실측: 이 프로젝트를 개선·배포하며 서버를 여러 번 재시작했지만 전 노드가 매번 스스로 복귀.
균질 Linux↔Linux에서도 SSH엔 구조적 한계가 남습니다 — 인바운드 도달성(NAT/방화벽 뒤 불가) · 1:N 팬아웃 · 지속성 · fleet 가시성 · 셸 밖 능력. 실측 한 방: 같은 리눅스 박스에 SSH inbound :22는 timeout(못 들어감)인데 DureClaw는 outbound로 붙어 exe까지 빌드했습니다. SSH는 전송 파이프, DureClaw는 fleet 버스 — 레이어가 다릅니다.

# GPU·Linux·Pi는 대기
SCENE 01 0:00 – 0:15
문제: Claude Code는 창 하나에서만
"Mac에서 Claude Code를 쓰고 있는데 — 옆에 GPU 서버가 그냥 놀고 있어요."

Mac 터미널에서 Claude Code 실행 중. 서버 터미널은 idle. 두 창을 번갈아 가며 수동으로 SSH → 복붙하는 불편함.
$ bash <(curl -fsSL
   dureclaw.baryon.ai/install)
✓ 서버 + MCP + Tailscale
SCENE 02 0:15 – 0:45
한 줄 설치 — 서버 + MCP 자동 등록
Mac 터미널에서: bash <(curl -fsSL dureclaw.baryon.ai/install)

자동 처리: Phoenix 서버 백그라운드 시작 → OAH_SECRET 생성 → Claude Code MCP 등록 → Tailscale IP 감지 → 워커 연결 명령어 출력까지 한 번에.
$ PHOENIX=ws://100.x:4000
   bash <(…/agent)
✓ builder@server 연결됨
SCENE 03 0:45 – 1:05
워커 머신에서 한 줄 연결
GPU 서버 터미널에서 install.sh가 출력한 명령어 복붙:
PHOENIX=ws://100.x.x.x:4000 bash <(curl -fsSL …/agent)

✅ builder@gpuserver 연결 완료 메시지. 대시보드 http://localhost:4000에서 에이전트 온라인 확인.
claude › /두레팀
"팀 설정해줘"
→ N개 머신에 fan-out
SCENE 04 1:05 – 1:25
Claude에게 팀 구성 지시
Claude Code 터미널: /두레팀 입력

Claude가 자동으로: 온라인 에이전트 스캔 → Work Key 생성 → 팀 매니페스트 구성 → 역할 배분.

팀 현황 출력: orchestrator@mac · builder@gpuserver
SCENE 05 1:25 – 2:30
두 머신이 동시에 — The Magic Moment
"프론트엔드 빌드는 Mac에서, 백엔드 테스트는 서버에서 동시에 돌려줘."

두 터미널이 동시에 움직인다. Mac: npm run build 실행 중 · GPU 서버: pytest tests/ 병렬 실행.

Claude가 양쪽 결과를 수집해 통합 리포트 출력. 전체 소요 시간: 직렬 대비 ~50% 단축.

설치 → 워커 연결 → 한 줄 지시 → 동시 실행 · 약 2.5분. 위 라이브 데모는 실제 시스템 캡처.
